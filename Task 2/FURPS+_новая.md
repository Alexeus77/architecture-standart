| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1    | Отображение списка доступных депозитов с актуальными ставками на сайте. 
| F2  |  Подача заявки на депозит, оставив свой номер телефона и ФИО                                        |              |
| F3    | Обработка заявки на депозит со стороны бекофиса                                 |              |
| F4    | Отображение списка доступных депозитов с актуальными ставками на в интернет банке. 
| F5  |  Подача заявки на депозит в интернет-банке, указав счёт и сумму депозита        
| F6  |  Подтверждение операции заявки на депозит в интернет-банке с помощью СМС-кода        
| F7  |  Информация по ставке по депозитам для сотрудников как бэк-офиса депозитов, так и бэк-офиса кредитов в АБС.
| F7  |  СМС-уведомления для клиента после подтверждения размера ставки и открытия депозита.        |              |
| U   | Удобство использования (Usability) |              |
| U1    | Интерфейс интернет банка будет максимально удобным для клиента                                |              |
| U2    | Пользователи при работе должны видеть привычные цвета и брендированные элементы
| R   | Надёжность (Reliability)           |              |
| R1    |  В интернет-банке и АБС данные при передаче надо защитить каким-то механизмом шифрования          
| R1    |  Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев                      |              |
| R3    |  В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку                      |              |
| P   | Производительность (Performance)   |              |
| P1    | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды       |              |
| S   | Поддерживаемость (Supportability)  |              |
| S1    | При доработках во всех системах нужно как можно больше использовать технологии, которые уже есть в банке. Например, базы данных MS SQL и Oracle                                |              |
|  S2   | Желательно, чтобы внутри банка уже была экспертиза — сотрудники понимали новые технологии хотя бы на уровне языков программирования                                |           
|  S3   |  Предусмотреть разработку документации для дальнейшего расширения системы                                |              |
|  S4   |  Предусмотреть использование резервного ЦОД в случае сбоя               |              |
|  S5   |  Если нужны очереди сообщений, то лучше использовать Kafka на перспективу                                |              |
| +R  | + Ограничения (Restrictions)       |              |
|  R1   | Учитывать, что АБС может масштабироваться только вертикально из-за своей базы данных                                |              |
|  R1   |  Реализовать доработку функционала работы с СМС силами команды разработки банка        |
|  R2   |  Текущая версия платформы интернет-банка несовместима с Kafka       |
|  R3   |  На этапе MVP предполагается, что заявку на открытие депозита обработает менеджер в бэк-офисе       |
|  R4   |  Используем по максимуму текущие разработки и технологии (MS SQL/ Oracle / PHP / React.js / ASP.NET MVC 4.5 / Java Spring Boot)       |
|  R5   |  Предусмотреть возможность использования Kafka в архитектуре       |
