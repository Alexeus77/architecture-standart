| R1    | Защита чувствительных данных |  В интернет-банке и АБС данные при передаче надо защитить каким-то механизмом шифрования

| P   | Производительность (Performance)   |              |
| P1    | Время отклика  | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды       |              |

| S1    | Переиспользование техноглогий и разработок | При доработках во всех системах нужно как можно больше использовать технологии, которые уже есть в банке. Например, базы данных MS SQL и Oracle                                |              |
|  S2   | Наличие экспертизы у команды | Желательно, чтобы внутри банка уже была экспертиза — сотрудники понимали новые технологии хотя бы на уровне языков программирования                                |           
|  S3   |  Документирование | Предусмотреть разработку документации для дальнейшего расширения системы                                |              |
|  S4   |  Резервный ЦОД | Предусмотреть использование резервного ЦОД в случае сбоя               |              |
|  S5   |  Брокера сообщений Kafka |  Если нужны очереди сообщений, то лучше использовать Kafka на перспективу                                |              |
| +R  | + Ограничения (Restrictions)       |              |

|  R2   |  Доработка функционала СМС | Реализовать доработку функционала работы с СМС силами команды разработки банка        |

|  R4   |  Ручная обработка заявки на этапе MVP | На этапе MVP предполагается, что заявку на открытие депозита обработает менеджер в бэк-офисе       |
|  R5   |  Ограничение по технологиям | Используем по максимуму текущие разработки и технологии (MS SQL/ Oracle / PHP / React.js / ASP.NET MVC 4.5 / Java Spring Boot)       |
|  R6   |  Ограничение по брокеру сообщений | Предусмотреть возможность использования Kafka в архитектуре       |
