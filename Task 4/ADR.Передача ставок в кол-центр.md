### <a name="_3bfxc9a45514"></a>**Функциональные требования**
|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| -: | :- | :- | :- |
| UC1  | Менеджер бэк-офиса           | Отправка файла со ставками по депозитам                   | Менеджер бэк-офиса получает актуальный файл в формате XLS со ставками по депозитам и перенаправляет его в в кол-центр организации и парнерский кол-центр                   |
| UC2  | Менеджер кол-центра           | Получает файл со ставками по депозитам          | Менеджер кол-центра получает актуальный файл в формате XLS
| UC3  | Менеджер партнерского кол-центра           | Получает файл со ставками по депозитам          | Менеджер кол-центра получает актуальный файл в формате XLS
### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**
|**№**|**Требование**|
| :-: | :- |
| 1  | Система кол-центра должна иметь доступ к актуальным депозитным ставкам
| 2  | Ставки должны передаваться в виде файла в формате XLS
| 3  | Ставки должны доступны партнерскому кол-центру
| 4  | Предусмотреть защиту файлов от несанкционированного просмотра

[Диаграмма Use cases](./ДиаграммаUseCases.puml)

Данная схема отражает требования к MVP, учитывает ограничения, включая невозможность использования API партнерским кол-центром.
### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Передача актуальных ставок по депозитам в реальном времени из АБС с использованием API.

**Недостатки, ограничения, риски**

Передача ставок по депозитам в виде файла раз в день имеет риск неактуальности ставок, а также риск ручной передачи неверного файла по ошибке. Такж повышается риск несанкционированного доступа к информации в файле.
